### [🚀 **Try it Live**](https://pythonragbotfinal-whu6uxgiz4hcnkofopnwtq.streamlit.app/) — no install needed, opens in your browser

A retrieval-augmented Python tutor: ask a question, get a short explanation plus a
grounded code example, built on a 68-topic Python knowledge base spanning basics,
data structures, functions, OOP, error handling, modules, and concurrency — plus a
timed **Practice Problems** mode with 53 classic coding challenges.

## What makes this different

- **Auto-tuned retrieval, not guessed.** `evaluation/evaluate_retrieval.py` benchmarks
  TF-IDF, BM25, embeddings, and 9 hybrid weightings against 136 ground-truth questions,
  and automatically picks the best-scoring configuration — no manually chosen constant.
- **Handles outdated information on purpose.** Deliberately conflicting current/outdated
  topics (e.g. `urllib.request` vs. the removed `urllib2`) prove the retrieval layer
  correctly prefers current, accurate answers over deprecated ones.
- **Scrapes real docs.python.org content**, with an automatic, per-topic fallback to
  curated text if a page can't be reached — the knowledge base never silently breaks.
- **Documented failures, not just successes.** `evaluation/error_analysis.md` records
  every real bug found while building this (and how it was fixed), not a hypothetical
  write-up.

## Building the knowledge base from docs.python.org

The 64 topics are no longer hand-written. `01_documents.py` loads them from
`data/scraped_documents.json`, which `00_scrape_documents.py` builds by
scraping the real explanation + code example for each topic straight from
docs.python.org (and packaging.python.org for the pip topic):

```bash
python 00_scrape_documents.py
```

- `data/sources.json` maps each topic to the exact page and section anchor
  (e.g. `for_while_loops` → `tutorial/controlflow.html#for-statements`).
- Fetched pages are cached in `data/scrape_cache/` so re-runs don't
  re-download anything.
- If a specific page/anchor can't be reached (offline, moved page, renamed
  anchor), **that one topic** — and only that one — falls back to a curated
  version baked into `01_documents.py`, so the bot never ends up missing a
  topic just because one scrape failed. `01_documents.py` also falls back to
  the full curated set automatically if you skip this step entirely.
- Re-run this any time you edit `data/sources.json`.

**Why chunking matters here:** every topic in `01_documents.py` is written to
stay under ~180 words (explanation + code example). `03_chunking.py` uses a
`chunk_size` of 180 words specifically so each topic survives as **one whole
chunk** — the explanation and its code example are never split apart into two
separate chunks. That is what keeps answers complete instead of getting cut
off mid-explanation or missing the code example. If you add a longer topic
later, either keep it under ~180 words or raise `chunk_size` accordingly.

## Evaluating and auto-tuning retrieval

`evaluation/evaluate_retrieval.py` measures retrieval quality the same way
Lab6, Lab7, and Lab8 did — Precision@3, Recall@3, Hit Rate@3, and Mean
Reciprocal Rank — but against this project's own 61 topics and 61
naturally-phrased ground-truth questions (`evaluation/ground_truth.py`),
none of which are copied verbatim from the topic titles.

It benchmarks TF-IDF as a reference baseline, then sweeps the hybrid weight
`alpha` from `0.0` (pure BM25) to `1.0` (pure embeddings) in steps of 0.1 —
which covers all three retrieval strategies (lexical, semantic, and hybrid)
in a single run, since BM25-only and embeddings-only are just the two edges
of the same hybrid formula used in `04_vector_representation.py`:

```bash
python evaluation/evaluate_retrieval.py
```

It automatically picks the best-scoring configuration (highest mean
reciprocal rank, tie-broken by Hit Rate@3) and writes it to
`data/best_config.json`. `04_vector_representation.py` reads that file at
startup, so **the live app automatically uses whichever alpha the
evaluation found best** — no manual code editing required. If the
evaluation has never been run, it falls back to `ALPHA = 0.6`, the value
that performed best in the original Lab7/Lab8 experiments.

Re-run the evaluation whenever you add or edit topics in `01_documents.py`;
`evaluation/evaluation_results.md` is regenerated with the full comparison
table, ready to show as evidence during project discussion.

## Current-vs-outdated conflict resolution

Four topics exist specifically to test this: `urllib_requests` (current) vs.
`python2_print_statement`, `distutils_deprecated`, and `urllib2_deprecated`
(all marked `is_current=False`, each pointing at the current doc it
conflicts with via a `replaces` field). When a question retrieves **both**
a current and its outdated counterpart, `06_retrieve_context.py` drops the
outdated one so the LLM never receives contradictory instructions. If only
the outdated source is relevant, it's kept but labeled `(OUTDATED — do not
recommend this, prefer current practice)` in the context, and the
`grounded_currency` prompt (see below) is instructed to warn the student
explicitly.

## Prompt variants

`07_prompting.py` defines three prompt strategies — `minimal`, `grounded`,
and `grounded_currency` (default, set via `PROMPT_VARIANT` in `.env`) — of
increasing strictness, ending with the one that explicitly handles
`(OUTDATED)` sources. Compare them directly on real test questions with:

```bash
python evaluation/compare_prompts.py
```

This writes `evaluation/prompt_comparison.md` with each variant's actual
answer to the same questions side by side.

## Error analysis

`evaluation/error_analysis.md` documents every real failure found while
building this project (a rejected valid question, missing topics, a
cross-lingual retrieval limitation, a crash on an empty LLM response, and
the outdated/current conflict handling above) — what caused each one and
what was changed, useful to reference directly during project discussion.

## Choosing a free LLM provider

You don't need a paid key to run this project — both options below are free:

**Option A — Google Gemini (default)**
1. Go to [aistudio.google.com/apikey](https://aistudio.google.com/apikey) and create a
   free API key.
2. In `.env`, set:
   ```env
   LLM_PROVIDER=gemini
   LLM_API_KEY=your_key_here
   LLM_MODEL=gemini-2.0-flash
   ```

**Option B — OpenRouter free models**
1. Create a free account at [openrouter.ai](https://openrouter.ai) (no card needed).
2. Go to Keys → Create Key.
3. In `.env`, set:
   ```env
   LLM_PROVIDER=openrouter
   LLM_API_KEY=your_key_here
   LLM_MODEL=meta-llama/llama-3.3-70b-instruct:free
   ```
   Free models are rate-limited (roughly 20 requests/minute, 200/day), which is
   plenty for a student project. The list of free models changes over time —
   browse current ones at `openrouter.ai/models?max_price=0` if the one above
   is no longer available.

Both providers work through the same OpenAI-compatible client, so switching
between them only means changing these three environment variables.

## Run locally

```bash
python -m pip install -r requirements.txt
python -c "import nltk; nltk.download('punkt'); nltk.download('punkt_tab'); nltk.download('stopwords'); nltk.download('wordnet')"
cp .env.example .env        # then paste your real LLM_API_KEY into .env
python 00_scrape_documents.py             # builds the knowledge base from docs.python.org
python evaluation/evaluate_retrieval.py   # optional but recommended: auto-tunes alpha
python 05_create_chroma_store.py
streamlit run streamlit_app.py
```

If you add or rename topics in `01_documents.py`, regenerate the sidebar list:

```bash
python build_topics_meta.py
```

## Deploying on Streamlit Cloud

1. Push this project to a GitHub repository (do **not** commit your real `.env`
   — `.gitignore` already excludes it).
2. On [share.streamlit.io](https://share.streamlit.io), create a new app pointing
   at `streamlit_app.py` in your repo.
3. Open **Manage app → Secrets** and add:
   ```toml
   LLM_PROVIDER = "gemini"
   LLM_API_KEY = "your_real_key_here"
   LLM_MODEL = "gemini-2.0-flash"
   ```
4. Deploy. `streamlit_app.py` reads from `st.secrets` automatically when no
   local `.env` is present.

## Notes

- API keys are never hardcoded in any `.py` file; they load from `.env`
  locally (via `python-dotenv`) or from Streamlit secrets when deployed.
- Answers are grounded only in the retrieved context. Internal retrieval
  details (scores, chunk ids) are never shown to the user or mentioned in the
  answer — only a clean explanation, a code example, and the related topics.
- If no topic in the knowledge base is relevant enough to the question, the
  assistant says so honestly instead of guessing.
